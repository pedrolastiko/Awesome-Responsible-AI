# Pillar 06 — Security

## Why it matters

AI introduces new attack surfaces (data poisoning, adversarial inputs, prompt injection, model theft) requiring dedicated controls.

## Key indicators / questions to assess it

- Is AI threat modeling integrated with security architecture reviews?
- Are model/data pipelines protected against tampering?
- Are red-team findings tracked and remediated?
- Do incident response plans explicitly include AI-specific incidents?

## Mapping table

| Framework | How security is addressed |
|---|---|
| ISO/IEC standards family | Security baselines support AI system hardening. |
| NIST AI RMF + GenAI profile | Includes misuse, robustness, and operational safeguards. |
| Sector guidance | Adds domain controls for critical infrastructure and safety contexts. |
| Industry frameworks | Provide practical secure MLOps/LLMOps controls. |
